投标文件识别系统Bid document recognition and analysis system

面向投标文件审阅，设计 OCR 与语义分析流程，涵盖结构化解读、内容归类、疑似异常核查及原文定位。For bid-document review, an OCR and semantic-analysis workflow is designed for structured interpretation, classification, potential-anomaly review, and source-page navigation.

工作内容Scope
需求分析、系统设计与界面原型Requirements, system design, and interface prototypes

项目背景Background

投标文件通常篇幅长、版式复杂，正文中混排表格、资质材料、合同与签名。人工在多个文件之间查找信息、比对内容和核对页码，容易出现遗漏。该项目围绕文件上传、结构化解析、内容分类和辅助核查，设计统一的文档审阅工作流。Bid documents are lengthy and mix prose with tables, qualifications, contracts, and signatures. Manually searching, comparing, and checking page references across documents is time-consuming and prone to omissions. The project designs a unified review workflow for upload, structured parsing, classification, and assisted inspection.

任务说明Task

以 PDF 或扫描文件为输入，按项目与标书组织资料，提取文本、表格及图片，生成可定位到原页的目录和内容解读；在此基础上提供分类归档、相似片段、签名一致性及疑似图像修改等分析入口。输出用于辅助人工复核，不能以相似度或模型分数直接认定违规。Accept PDF or scanned inputs, organize files by project and bid, extract text, tables, and images, and provide a table of contents and interpretations linked to source pages. Analysis views cover categorization, similar passages, signature consistency, and possible image edits. Outputs assist human review; similarity or model scores alone do not establish misconduct.

  • 原文与分析结果并列展示，目录、表格和异常线索保留页码跳转，便于核验识别内容。Display source pages beside analysis, with page links for headings, tables, and flagged items so results can be checked against the original.
  • 所提供材料为需求、概要设计、详细设计及界面原型，以下展示系统设计内容，不列未经测试的识别率或效率提升。The supplied materials comprise requirements, high-level and detailed designs, and interface prototypes. The following presents those designs without unmeasured accuracy or efficiency claims.

系统和关键技术System and key technologies

设计采用用户交互层、服务层和基础设施层。WebService 负责文件、任务和业务接口，算法服务独立执行 OCR 与语义分析；数据库保存项目元数据和分析结果，文件存储保存原始文档与派生资源。Vue 页面和 REST API 提供交互与集成入口。The design separates user interaction, services, and infrastructure. WebService manages files, tasks, and business interfaces; algorithm services handle OCR and semantic analysis. A database stores project metadata and analysis results, while file storage retains originals and derived resources. Vue pages and REST APIs provide user and integration interfaces.

  • PDF 解析与 OCRPDF parsing and OCR：: 方案使用 PyPDF2 / PyMuPDF 提取可读取文本与内嵌图片，对扫描页进行预处理与 Tesseract OCR；页码与区域位置贯穿后续解析，支持原文追溯。The design uses PyPDF2 / PyMuPDF for readable text and embedded images, and preprocessing with Tesseract OCR for scanned pages. Page numbers and region coordinates remain associated with extracted content.
  • BERT / DistilBERT / T5BERT / DistilBERT / T5：: 根据标题格式与语义组织章节层级，以文本分类归并合同、财务、资质等内容，再对已提取文本生成章节解读；这些模型作为设计选型描述。Use heading format and semantics to organize sections, classify extracted text into contracts, financial content, qualifications, and related groups, then generate section interpretations. These models are described as design choices.
  • 表格结构与图文索引Table structure and visual indexing：: 设计以 TableNet 定位表格区域，结合 OCR 提取单元格文本；图片与表格均保留所属页和上下文，便于原文查看和结构化归档。The design uses TableNet to locate tables and OCR to extract cell text. Images and tables retain their source page and surrounding context for inspection and structured archiving.
  • 语义相似与实体关系Semantic similarity and entity relations：: 以 Sentence-BERT 语义表示比较同类文本，结合命名实体识别组织人员、单位和项目关系；分析结果作为检索与人工核查线索。Use Sentence-BERT representations to compare related texts and named-entity recognition to organize people, organizations, and projects. Results serve retrieval and human review.
  • 任务分发与结果复用Task dispatch and result reuse：: 请求先校验参数并查询已有分析结果，未命中时才调用对应算法服务；结果写入数据库后返回前端，减少同一文件的重复分析，并保持业务与算法模块解耦。Validate requests and look up existing analysis before invoking an algorithm service on a cache miss. Persist and return results, reducing repeated analysis and decoupling business logic from algorithms.
