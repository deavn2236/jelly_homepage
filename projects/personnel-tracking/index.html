人员识别定位与轨迹回放系统Personnel identification, localization, and trajectory playback

面向人员身份与位置追踪，融合视频检测、重识别与雷达定位，实现同步监控、轨迹回放，并完成双路相机试运行。For identity and location tracking, video detection, re-identification, and radar localization enable synchronized monitoring and trajectory playback, with two-camera trial operation.

项目背景Background

园区与厂区的视频监控通常只能提供分散的画面，难以持续回答“有哪些人员、位于何处、如何移动”。本系统将视频中的检测与身份信息同雷达空间定位结合，在统一 Web 平台中呈现实时人员轨迹与历史记录，连接现场观察、身份查询和轨迹回溯。Separate surveillance feeds make it difficult to determine who is present, where each person is, and how they moved. This system combines visual detection and identity cues with radar-based spatial localization. A unified Web platform connects live observation, identity lookup, and historical trajectory review.

任务说明Task

接入多路网络相机、雷达点云和标定参数，完成检测跟踪、身份确认、世界坐标定位与轨迹存储。前端同步展示视频框与轨迹，支持实时监控、历史回放、人员档案和多视角 ReID 图片维护；实时链路还需避免旧检测框叠加到新画面、后处理积压和服务异常中断。Ingest network cameras, radar point clouds, and calibration parameters; detect and track people, confirm identity, estimate world coordinates, and store trajectories. The frontend synchronizes video overlays with trajectories and supports live monitoring, playback, personnel records, and multi-view ReID galleries. The real-time pipeline must prevent stale overlays, processing backlogs, and service interruptions.

系统和关键技术System and key technologies

系统采用前后端分离架构，算法服务与独立视频流服务分工协作，数据层保存人员档案、检测记录与事件。身份图的跨相机关联扩展按受控测试启用，日常运行以报告中已开启的功能为准。The architecture separates frontend and backend responsibilities, and runs algorithm and video-stream services independently. The data layer stores personnel records, detections, and events. Extended cross-camera identity-graph association is enabled for controlled tests; normal operation uses the functions documented as active in the report.

  • YOLO + ByteTrackYOLO + ByteTrack：: 对相机帧进行人员检测与多目标跟踪。解码、检测、跟踪和叠加发布在每相机关键链路中顺序完成，避免重型后处理阻塞视频更新。Detect people and maintain multi-object tracks. Decoding, detection, tracking, and overlay publication run sequentially in each camera’s critical path, isolated from expensive post-processing.
  • InsightFace / FastReID / 步态证据InsightFace / FastReID / gait cues：: 以人脸锚点优先确认身份，ReID 和步态作为辅助证据；通过置信度差距与连续帧确认约束身份切换，降低身份抖动。Prioritize face anchors for identity confirmation, with ReID and gait as supporting cues. Confidence margins and confirmation across successive frames constrain identity changes.
  • 源帧对齐与雷达融合Source-frame alignment and radar fusion：: 以相机源时间戳贯穿解码、检测、雷达匹配及前端叠加；雷达点云按 0.1 秒时间窗匹配视频，完成投影、背景剔除和世界坐标输出。Carry camera source timestamps through decoding, detection, radar matching, and overlays. Match radar points to video within a 0.1-second window, project points, remove background, and output world coordinates.
  • 有界队列与独立流服务Bounded queues and independent streaming：: 将融合、轨迹维护与落盘放入每相机容量为 2 的后处理队列，满时保留新任务；视频流按源时间同步播放，仅使用精确同帧结果或安全插值叠加。Place fusion, trajectory maintenance, and persistence in per-camera post-processing queues of capacity two, retaining recent tasks when full. Streaming follows source time and overlays only exact-frame results or safe interpolation.
  • Vue 3 + FastAPI + MySQLVue 3 + FastAPI + MySQL：: 以 Vue 3 / Element Plus 构建 Web 界面，FastAPI 提供算法与业务接口，MySQL 保存结构化记录；Nginx 统一入口，WebSocket 更新轨迹元数据，多 GPU 复用检测与身份服务。Build the Web interface with Vue 3 and Element Plus, serve algorithm and business APIs through FastAPI, and persist records in MySQL. Nginx provides a unified entry point, WebSocket updates trajectory metadata, and multiple GPUs share detection and identity workloads.

部署与工程实现Deployment and engineering

汇报中的运行环境为单机服务器，配备 4 张 NVIDIA RTX 3090；相机输入采用 H.264 视频，雷达输出点云，标定文件维护传感器间坐标关系。视频流、算法服务和统一入口分别运行，启动流程包含健康检查与资源调优；无可用 GPU 时支持 CPU 回退。The reported deployment uses a single server with four NVIDIA RTX 3090 GPUs, H.264 camera feeds, radar point clouds, and calibration files for sensor coordinate transforms. Streaming, algorithm services, and the unified entry point run separately. Startup includes health checks and resource tuning, with CPU fallback when a GPU is unavailable.

  • 看门狗区分人工停止、服务挂起与进程退出，按状态恢复；慢客户端和消息大小使用有界保护。A watchdog distinguishes manual stops, hung services, and terminated processes; bounded protections limit slow clients and oversized messages.
  • 每次监控启停建立独立后处理会话，旧任务在产生副作用前校验会话，避免历史结果污染新一轮监控。Each monitoring session has its own post-processing state. Old tasks validate their session before side effects, preventing stale results from entering a new session.

演示与结果Demonstrations and results

视频展示多路相机中的人员检测与同一全局坐标视图中的轨迹更新。2026 年 10 月 19 日汇报记录为：配置 5 路相机，其中 2 路在线试运行，累计检测记录 10,863 条；预览与处理循环配置为 30 FPS。该运行记录不等同于识别准确率或定位误差的专项测试结果。The recording shows person detections from multiple cameras alongside trajectory updates in a shared coordinate view. The report dated October 19, 2026 records five configured cameras, two online in trial operation, and 10,863 accumulated detection records, with preview and processing loops configured at 30 FPS. These operation figures do not constitute dedicated recognition-accuracy or localization-error measurements.
